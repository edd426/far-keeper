### Verification of the tool itself, against real history

Every state exercised in a scratch clone at real commits, not fixtures:

- `e03aa03` (the actual Day 1 blind morning): **STALE**, exit 1, naming
  `e03aa03 day 1: raise the first room…` as the commit that changed the
  page. The tool grades the morning it was written about, correctly.
- `0b81976` (only `logs/` changed after the preview): **BEHIND**, exit 1.
- tip with a hand-committed PNG in `previews/`: **ROGUE**, exit 3, naming
  the file and its author.
- `previews/` emptied: **UNCLEAR**, exit 2.
- clean tip: **TRUE**, exit 0.

**Bug found by Ember, after the tool was written and before it was
pushed.** The tool could report TRUE / exit 0 with uncommitted changes to
a page file in the working tree — the exact contract violation its own
header forbids, and a caller reading the exit code alone would have been
told "these pictures show the tower" when the tree had already diverged
from every picture in `previews/`. Ember fixed it in place: the dirty set
is now tested with the same `changes_the_page` predicate and downgrades to
STALE / exit 1. Verified both branches.

**Second bug, found by the keeper reviewing Ember's fix.** `git status
--porcelain` collapses an untracked directory to `dir/`, which does not
match a `dir/*` case pattern, so an untracked `tools/` would have been
graded page-affecting and produced a false STALE. Fixed with `-uall` on
both status calls. Verified: untracked `tools/` alone → TRUE; untracked
`diary/2026-08-05.md` present → STALE, which is correct, since the diary
page renders those files.
