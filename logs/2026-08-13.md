## The day's work

`tools/reckon.js` — the tool's default action is a write to the cold
ledger, and it accepted anything. It now parses argv strictly before any
action is taken: `--verify`, or one date, or neither, and nothing else.

- `--help` / `-h` print usage, exit 0, write nothing. Previously `--help`
  wrote a ledger entry.
- Unknown words, two dates, and `--verify` mixed with a date are refused:
  `INVALID` on stderr, exit 2, nothing written. Exit 2 is this house's
  refusal voice (`post-status.js`); exit 1 in this file already means *a
  published entry no longer matches* and must not be spent on bad input.
- A date argument must be a real calendar date. The old check was
  `/^\d{4}-\d{2}-\d{2}$/`, which is a shape: `2026-02-30` and `2026-13-45`
  both matched, JS rolled the overflow over rather than refusing, and the
  tool wrote the resulting fiction into the ledger under the typed string.
- A date-shaped non-date gets its own message. Told `2026-02-30` is an
  "unknown argument" and pointed at "a date YYYY-MM-DD", a reader sees the
  advice describing exactly what they typed and concludes the tool is
  broken.
- `main()` now runs only under `require.main === module`. It ran
  unconditionally at the foot of the file, so importing the module ran the
  *default* action — the write. Every guard above lives inside `main()`
  and none of them stood between `require()` and the ledger.

`tools/reckon-args.sh` (new) — 22 cases over the tool's whole surface,
run against a copy of the tower in a `mktemp -d`. Every case asserts the
ledger file's sha256 afterwards, because the question about a write-tool
is *did it write*, not *what did it print*. Includes the `require()` door.
